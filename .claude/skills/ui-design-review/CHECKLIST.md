# UI design review — checklist

Опорный список для скилла `ui-design-review`. Группы упорядочены по severity вниз: первые блокируют мерж, последние — стиль.

## 1. Контраст и читаемость (WCAG 2.1 AA)

| Что                                  | Порог                                                       | Как проверить                                                              |
| ------------------------------------ | ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| Body text vs background              | 4.5:1                                                       | Посчитать ratio для `var(--color-fg)` на `var(--color-bg)` и подобных пар. |
| Крупный текст (≥18pt или ≥14pt bold) | 3:1                                                         | То же для h1/h2 если используют другую пару.                               |
| Иконки и UI-индикаторы               | 3:1                                                         | Цвет иконки на фоне.                                                       |
| Focus ring                           | 3:1 против фона                                             | Проверить `outline-color` или `--color-focus-ring`.                        |
| Placeholder/disabled                 | 4.5:1 предпочтительно (WAI-ARIA не требует, но UX-полезно). | grep `placeholder`/`disabled`.                                             |

⚠️ Используется `color-mix(...)` — оценить эффективный hex. `color-mix(in srgb, X 65%, transparent)` на bg даёт fg ≈ 65% от X-к-bg.

## 2. Визуальная иерархия

- Heading-scale: h1 крупнее h2 крупнее h3, через `--fs-*`. Никаких h1 равных h3 «по дизайну».
- Не пропускать уровни: после h2 нельзя h4 (a11y + читаемость).
- Spacing rhythm: gap внутри секции из шкалы `--space-*`. Не миксовать `--space-4` (16) и произвольные 14px.
- Один акцентный элемент на «экранную ширину» — иначе фокус размывается.

## 3. Консистентность

| Что               | Что искать (grep)                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------- |
| Хардкод hex       | `#[0-9a-fA-F]{3,6}` в `*.astro`, `*.css`, `*.tsx` (за вычетом SVG path / кода в blog-постах). |
| Хардкод px        | `[0-9]+px` (можно ослабить до значений ≥4 которые не из шкалы).                               |
| Дубликаты токенов | Проверить, что не вводится `--color-text` рядом с `--color-fg`.                               |
| `@apply`          | Запрещён. Везде.                                                                              |
| Шрифты            | Только `var(--font-serif/sans/mono)` или Tailwind utility, замапленный на них.                |

## 4. Респонсив

| Брейкпоинт        | Минимум, что должно работать                                                 |
| ----------------- | ---------------------------------------------------------------------------- |
| < 640px (mobile)  | Layout одно-колоночный, навигация в drawer/hamburger, шрифты не меньше 14px. |
| 640–1024 (tablet) | Двух-колоночный (sidebar + content), либо stack по необходимости.            |
| > 1024 (desktop)  | Полная композиция (sidebar + content + TOC если есть).                       |

Минимум — есть отдельные правила для mobile (через media-query или Tailwind responsive utility). Если компонент чисто desktop — обоснуй явно.

## 5. Dark mode

- Все цветовые токены, использованные в компоненте, имеют counterpart в `@media (prefers-color-scheme: dark)` блоке `tokens.css`. Проверить grep'ом по `--color-` именам.
- Тени для dark — собственные (`--shadow-soft`/`--shadow-lifted` уже переопределены в dark-блоке, не использовать light-значения вручную).
- SVG/иконки: если используется `currentColor` — норм. Если фиксированный hex — fail (придётся хардкодить под обе темы).

## 6. Motion и `prefers-reduced-motion`

- `transition`/`animation` длительности — через `--dur-*`. Никаких `200ms` напрямую.
- Easing — через `--ease-*`.
- В `prefers-reduced-motion` `--dur-*` обнуляются автоматически. Если используешь жёсткий ms — нужен явный `@media (prefers-reduced-motion: reduce) { ... }` override.

## 7. A11y surface

| Элемент                                   | Требование                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `<img>`                                   | `alt` обязателен (для декоративных — `alt=""`).                                                      |
| `<input>`                                 | Связан с `<label>` через `for`/`id` или `aria-label`.                                                |
| `<button>` с иконкой только               | `aria-label` или visible text через `.visually-hidden`.                                              |
| `<button>` с текстом                      | OK.                                                                                                  |
| Кастомные интерактивные элементы          | Используют нативный тег если возможно. Если нет — `role`, `tabindex="0"`, keyboard handlers.         |
| Focus-visible                             | `:focus-visible` styled. `outline: none` без замены — fail.                                          |
| Модалки/диалоги                           | `aria-modal="true"`, focus trap, восстановление focus, Escape закрывает.                             |
| Цвет как единственный носитель информации | Дополнить иконкой/текстом (например, ошибка — не только красный, но и иконка ⚠ или текст «Ошибка:»). |
| Skip-link                                 | На страницах с длинной навигацией — `<SkipLink />`.                                                  |
| Заголовки страницы                        | Один h1 на страницу.                                                                                 |

## 8. Tone (минор, но важно)

- Жанр сайта — Editorial × Technical. Тяжёлые drop-shadows, неоновые градиенты, эмодзи в UI — против стиля.
- Серифные шрифты — для статичного контента (заголовки), не для UI.
- Mono — для технического (код, KBD, ID). Не для navigation.
- Не более одного акцент-цвета (`--color-accent`) одновременно в видимой области.

---

## Severity rubric

- **🔴 Critical:** WCAG нарушения, отсутствие keyboard-доступности, отсутствие dark counterpart для нового цвета, broken focus-visible.
- **🟡 Important:** Хардкод вместо токена, отсутствие mobile breakpoint, motion не уважает `prefers-reduced-motion`, дубликат токена.
- **🟢 Nit:** Не идеальная пара токенов (можно подобрать лучше), маргинальная иерархия, перебор с акцентом.
