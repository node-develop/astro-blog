# UI design review

## Цель

Единый чек-лист дизайн-ревью. Запускается после визуальных изменений (компоненты, layouts, стили) или перед мержем PR. Возвращает severity-tagged отчёт с конкретными цитатами файлов и строк.

## Когда запускать

- После изменений в `src/components/`, `src/layouts/`, `src/styles/`, `src/components/admin/`.
- Перед мержем PR, который трогает визуальный слой.
- Ad-hoc, если кто-то говорит «выглядит странно, посмотри».

## Что НЕ делает

- Не редактирует файлы (`Write`/`Edit` отключены).
- Не запускает дев-сервер, не делает скриншоты.
- Не пишет финальный код. Если требуются правки — формулирует их как задачи для `frontender` или указывает токен из `design-system-tokens`.

## Шаги

1. **Определи зону ревью.** Если есть git-диф — читай только изменённые файлы (`git diff --name-only main…HEAD` через Bash недоступен; пользователь может передать список). Иначе — задай вопрос: «какие файлы ревью?».
2. **Прочитай `src/styles/tokens.css`** целиком — чтобы знать палитру, шкалу, семейства.
3. **Прочитай `CHECKLIST.md`** рядом — основная рабочая опора.
4. **Пройдись по чек-листу** для каждого файла:
   - ✅ pass — пункт соблюдён.
   - ⚠️ warn — соблюдён частично или не критично, но стоит обратить внимание.
   - ❌ fail — нарушение, требует фикса.
5. **Контраст:**
   - Найди все пары текст/фон (через grep по `color:` и `background:`).
   - Если используются токены — посмотри hex в `tokens.css`.
   - Посчитай WCAG contrast ratio. Body ≥ 4.5:1; крупный текст (≥18pt или ≥14pt bold) ≥ 3:1.
   - Если используется `color-mix(in srgb, … N%, …)` — оцени по эффективному hex (опиши приближение в отчёте).
6. **Респонсив:**
   - Найди media-queries в файле и в импортируемых стилях.
   - Должны быть отдельные правила для `< 640px` (mobile) и/или `>= 1024px` (desktop). Минимум — один из брейкпоинтов покрыт.
7. **Dark mode:**
   - Все цветовые токены, использованные в файле, должны иметь counterpart в `@media (prefers-color-scheme: dark)` блоке `tokens.css`. Если используется hex напрямую — fail.
8. **Motion:**
   - Все `transition`/`animation` с длительностями — через `--dur-*` и `--ease-*`. Жёсткие миллисекунды — fail.
   - Проверь, что компонент уважает `prefers-reduced-motion` (либо через токены, которые обнуляются, либо через явный media-query).
9. **A11y surface:**
   - `<img>` без `alt` (кроме декоративных с `alt=""`) — fail.
   - `<input>` без `label` или `aria-label` — fail.
   - `<button>` с иконкой без `aria-label` — fail.
   - Focus-visible виден (нет `outline: none` без замены) — fail если нарушено.
   - `role`/`aria-*` корректны (нет `role="button"` на нативном `<button>`, нет `aria-required-children` нарушений).
   - Модалки — focus trap, `aria-modal="true"`, восстановление focus при закрытии.
10. **Сформируй отчёт** в формате ниже.

## Формат отчёта

````
# UI design review — <зона>

## Сводка
- 🟢 Всё ок: <N>
- 🟡 Warnings: <N>
- 🔴 Failures: <N>

## Critical
### `src/components/Foo.astro:42`
**Что:** color-contrast 3.1:1 (требуется 4.5:1).
**Цитата:**
```css
color: var(--color-fg-subtle); background: var(--color-bg-elevated);
````

**Фикс:** заменить на `var(--color-fg-muted)` (4.7:1) или поднять контраст самого `--color-fg-subtle`. Делегировать → `frontender` / `design-system-tokens`.

## Important

### `src/layouts/BaseLayout.astro:78`

**Что:** Хардкод `padding: 14px 22px` — не из шкалы `--space-*`.
**Фикс:** `padding: var(--space-3) var(--space-5)` (12 24) или ввести `--space-3-5` через `design-system-tokens`. Делегировать → `frontender`.

## Nit

### `src/components/Card.astro`

**Что:** Используется `--shadow-lifted` для hover-карточки в списке. Обычно достаточно `--shadow-soft`.

## Что прошло (✅)

- Все цвета имеют dark counterpart.
- Focus-visible виден на всех интерактивных элементах.
- Motion использует `--dur-base` + `--ease-out`.

```

## Принципы

- **Конкретно.** Каждое замечание — файл, строка, цитата, фикс. Нельзя писать «улучшите типографику» — нужно «увеличьте `--lh-relaxed` до 1.75 для prose, потому что …».
- **Severity-honest.** Critical — реально ломает доступность/читаемость. Important — нарушение системы, но текущее значение работает. Nit — стилевая придирка.
- **Не выдумывай токены.** Если предлагаешь использовать `--color-X`, сначала проверь, что он есть в `tokens.css`. Если нет — предложи добавить через `design-system-tokens`.
- **Не делай работу `frontender`-а.** Ревью указывает что и где, но не пишет финальный код. Эскизы фиксов — в комментариях, не в файлах.
```
