Ссылка на документацию в конце статьи не подтверждает автоматически каждое утверждение. Нужна связь между конкретной фразой, источником и проверкой. Этот урок заменяет прежнюю таблицу с безусловными отметками «подтверждено», в которой сами проверки были неточными.

## Карта исправлений

| Прежнее утверждение                              | Что исправлено                                            |
| ------------------------------------------------ | --------------------------------------------------------- |
| @-импорты уменьшают стартовый контекст           | Импортированный текст загружается; это организация файлов |
| allowed-tools — жёсткий whitelist skill          | Это предварительное разрешение инструментов               |
| memory: read-only задаёт память subagent         | Используются документированные scopes памяти              |
| Team автоматически блокирует редактируемые файлы | Назначение задачи не защищает каждый исходный файл        |
| JSON action:block универсально блокирует hook    | Протокол зависит от события                               |
| .mcp.local.json — стандартный local scope        | Local MCP хранится в ~/.claude.json                       |
| /cost показывает вчерашние расходы               | Это информация текущей сессии                             |
| У всех задач фиксированная экономия 65–80%       | Нужны usage и условия конкретного измерения               |

Подробности и ссылки находятся в соответствующих уроках. Эти исправления не означают, что любая новая версия клиента будет вести себя точно так же: проверять нужно установленную версию.

## Три вида доказательств

**Документация** устанавливает заявленный контракт. **Исходный код** помогает понять реализацию конкретной версии. **Запуск** показывает поведение в конкретной среде. При расхождении сохраните версии и минимальный пример, а не выбирайте более удобный источник.

Для команды сначала смотрите `--help`. Для frontmatter — схему нужного клиента, а не соседнего продукта. Для SDK — версию пакета и компилируемый минимальный пример. Для цены — провайдера, дату и весь состав расходов.

## Шаблон записи

```text
Утверждение:
Версия и среда:
Первичный источник и дата проверки:
Минимальный пример:
Наблюдаемый результат:
Что не проверено:
```

Заполните его для одного полезного вам утверждения. Например: «этот hook запускается после Edit». Сначала воспроизведите успех, затем намеренно сломайте matcher. Если вы не можете отличить оба случая, проверка недостаточна.

## Как читать бенчмарк

Ищите набор задач, критерий успеха, число попыток, исходные результаты и описание среды. Отсутствующие данные нельзя заменить личной уверенностью автора. Особенно осторожно переносите скорость генерации на скорость завершения программной задачи.

В этом курсе убраны неподтверждённые проценты, выдуманные команды и обещания готового Travel Agent. Примеры обозначены как учебные, а места для собственных измерений не заполнены придуманными цифрами.

## Куда сообщить об ошибке

Пришлите URL, точную фразу, версию инструмента и минимальный пример через [контакты](/contact/). Не отправляйте секреты и полный рабочий лог с чужими данными. Такое сообщение позволяет проверить и исправить материал предметно.
