Допустим, перед каждой правкой API вы просите агента найти схему запроса, обработчик и тесты. Вместо того чтобы заново писать эту просьбу, можно сохранить её как навык. В Claude Code такие процедуры называются _skills_ и описываются в файле SKILL.md.

Навык полезен, когда у процедуры есть понятный вход и результат. В нашем примере вход — адрес API, а результат — найденные расхождения между описанием и кодом.

## Создаём первый навык

Положите файл по пути `.claude/skills/review-contract/SKILL.md`:

```markdown
---
name: review-contract
description: Сверяет описание API с обработчиком и тестами.
disable-model-invocation: true
---

Проверь указанный адрес API.

1. Найди схему запроса, обработчик и описание ответа.
2. Сравни обязательные поля, ошибки и проверку доступа.
3. Найди тесты правильного и неправильного запроса.
4. Перечисли расхождения и укажи файлы.
5. Отдельно скажи, запускал ли ты тесты или только прочитал их.

Не меняй файлы: результат этой задачи — список наблюдений.
```

Начальный блок между `---` — настройки навыка. Остальной текст — сама процедура. Запустите её командой `/review-contract` и укажите адрес, который нужно проверить.

## Что означают настройки

`disable-model-invocation: true` оставляет запуск пользователю: модель не должна самостоятельно выбирать этот навык. Поле `allowed-tools`, если вы его добавите, предварительно разрешает перечисленные инструменты на ход, в котором навык вызван. По текущей документации это разрешение заканчивается со следующим сообщением пользователя. Оно не делает остальные инструменты недоступными.

Ещё одна настройка, `context: fork`, запускает навык в отдельном контексте помощника. Это не отдельная файловая система. Подробности и допустимые поля перечислены в [справочнике навыков](https://code.claude.com/docs/en/skills).

## Проверяем на известной ошибке

Возьмите учебный обработчик: по описанию дата обязательна, но код принимает пустую строку. Запустите навык. Он должен назвать это расхождение и показать место в коде. Общий совет «улучшить проверку данных» недостаточен.

Затем дайте правильный обработчик. Навык должен уметь ответить, что расхождений не обнаружено. Иначе он будет придумывать замечания ради заполнения отчёта.

## Как улучшать процедуру

После нескольких запусков исправляйте конкретные затруднения. Агент не находит схему — добавьте путь. Читает ненужный справочник целиком — укажите, когда обращаться к нему. Если нужен скрипт, сначала проверьте его вручную и только потом включайте в процедуру.

Для действий, которые должны запускаться по событию, есть другой механизм — [обработчики hooks](/courses/claude-code-guide/05-hooks/).
