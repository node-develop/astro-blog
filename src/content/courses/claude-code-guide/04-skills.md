Skill имеет смысл, когда вы регулярно повторяете одну процедуру: проверяете контракт, готовите описание PR или разбираете типовую ошибку. Начните с процедуры, которую можно выполнить вручную. Иначе в SKILL.md получится длинный список пожеланий без понятного результата.

## Пример: ревью API-контракта

Создайте `.claude/skills/review-contract/SKILL.md`:

```markdown
---
name: review-contract
description: Проверяет изменение API-контракта по исходникам и тестам.
disable-model-invocation: true
---

Проверь контракт указанного endpoint.

1. Найди схему входа, обработчик и описание ответа.
2. Сравни обязательные поля, статусы ошибок и авторизацию.
3. Найди тест корректного и некорректного запроса.
4. Верни таблицу расхождений с путями файлов.
5. Не утверждай, что тест выполнен, если ты только прочитал его.
```

Вызовите его как `/review-contract`, добавив endpoint в запрос. Сначала используйте маленький локальный пример: схема требует дату, а обработчик принимает пустую строку. Ожидаемый результат — конкретное расхождение, а не общий совет улучшить валидацию.

## Что означают настройки

Актуальные поля и синтаксис опубликованы в [справочнике skills](https://code.claude.com/docs/en/skills). `disable-model-invocation` оставляет запуск пользователю. `allowed-tools` предварительно разрешает перечисленные инструменты; это не список единственных доступных инструментов и не песочница. `context: fork` меняет контекст выполнения, но сам по себе не изолирует файловую систему.

Не добавляйте поле только потому, что его название выглядит правдоподобно. Проверьте поддержку в используемой версии и различайте Claude Code skill и пакет для другого клиента.

## Как развивать skill

После нескольких запусков соберите ошибки. Если агент не понимает, где схема, добавьте точный путь. Если повторяет длинные справочники, вынесите их в references и дайте обычную ссылку с условием чтения. Если процедура зависит от стороннего скрипта, документируйте его вход, выход и способ локальной проверки.

Скрипт должен оставаться понятным вне агента. Сначала запустите его вручную на тестовых данных. Затем проверьте, что skill передаёт те же аргументы и правильно обрабатывает неуспех.

## Критерий приёмки

Skill находит подготовленное расхождение, указывает доказательство и не меняет файлы без задачи на исправление. Повторите на корректном контракте: отсутствие проблемы тоже должно быть допустимым результатом.
