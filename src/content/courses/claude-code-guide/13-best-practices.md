Работа с агентом начинается не с выбора самой мощной модели. Сначала нужно понять, что сейчас происходит в проекте и какое поведение требуется изменить. Это особенно важно, когда в папке уже есть незавершённые правки.

Хорошая задача помещается в несколько предложений. Например: «Форма принимает дату возвращения раньше даты выезда. Исправь проверку. Правильный диапазон должен по-прежнему приниматься».

## Перед началом

Посмотрите состояние рабочей копии:

```bash
git status --short
git diff
```

`git diff` показывает изменения отслеживаемых файлов, ещё не добавленные в индекс. Новые файлы он не показывает, поэтому нужен и `git status`. Для уже подготовленных к коммиту изменений используйте `git diff --cached`.

Прочитайте инструкции проекта и найдите существующие команды проверки. Не очищайте папку и не перестраивайте историю Git поверх чужой незавершённой работы.

## Пока агент работает

Просматривайте изменения небольшими частями. Если вместе с проверкой даты внезапно меняется библиотека или соседний модуль, выясните причину. Иногда такая правка нужна, но она должна быть связана с задачей.

Когда тест падает, сначала прочитайте ошибку. Повторный запуск полезен при временном сбое, но не исправляет неверное условие в коде. Попросите агента объяснить, какое поведение проверяется и почему результат не совпал с ожидаемым.

## Перед коммитом

Проверьте все изменения, включая новые файлы и настройки. Запустите проверки, которые относятся к задаче, и отдельно посмотрите результат глазами пользователя, если менялось видимое поведение.

Короткий итог может выглядеть так:

> Обратный диапазон дат теперь отклоняется. Проверены неверный и правильный диапазоны. Отображение ошибки в мобильной форме тоже проверено. Поиск у внешнего поставщика в этой задаче не менялся.

Такой отчёт полезнее длинного перечня действий: из него видно, что получилось и где заканчивается проверка.

## Что сохранять для следующей задачи

В CLAUDE.md переносите устойчивые правила проекта. Подробности отдельной ошибки оставьте в описании задачи или изменении. Перед новой сессией запишите незавершённое и следующий шаг.

Если одни и те же ошибки повторяются, выберите несколько случаев и найдите общую причину. Это могут быть непонятные требования, устаревшая инструкция или неудобный инструмент. Меняйте именно эту часть процесса.

## Работа с внешними данными

Текст из файла или сайта может содержать инструкции, которым не стоит следовать. Это один из способов внедрения посторонних команд — _prompt injection_. Простое экранирование текста не решает проблему целиком. Разделяйте данные и инструкции, ограничивайте доступ и проверяйте [разрешения Claude Code](https://code.claude.com/docs/en/permissions).

Для упражнения возьмите завершённое изменение и объясните связь «задача → правка → проверка». В заключительном уроке научимся [так же проверять технические утверждения](/courses/claude-code-guide/14-claims-verification/).
