Когда вы просите продолжить работу, модели нужен материал для следующего ответа: переписка, инструкции, прочитанный код и результаты команд. Всё это составляет контекст. Его объём ограничен; слишком большая история не помещается в один запрос.

Кэш решает другую задачу. Если начало запроса уже обрабатывалось, сервис может использовать эту работу повторно. Это называют _prompt caching_, или кэшированием запросов. Кэш не хранит за вас описание незавершённой задачи и не заменяет передачу нужных данных.

## Три понятия, которые легко спутать

| Понятие           | Для чего нужно                                              |
| ----------------- | ----------------------------------------------------------- |
| Окно контекста    | Ограничивает объём материала в запросе                      |
| История разговора | Содержит сообщения и результаты предыдущих действий         |
| Кэш запроса       | Позволяет повторно использовать обработанное начало запроса |

В Claude Code команда `/context` помогает посмотреть расход контекста. Доступное окно зависит от выбранной модели и условий доступа; сверяйте его с [настройками моделей](https://code.claude.com/docs/en/model-config), а не с однажды записанным числом.

## Как проверить пользу кэша

Представьте длинную инструкцию по подбору маршрутов. Она одинакова для нескольких запросов, меняются только города и даты в конце. Такая повторяющаяся часть подходит для проверки кэша.

В тестовом API-приложении включите кэширование по [документации Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Убедитесь, что начало запроса достаточно длинное: минимальный размер для кэширования зависит от модели. Короткое «привет» для этого опыта не подходит.

Отправьте запрос дважды, не меняя повторяющуюся часть. Сохраните раздел `usage` — сведения об использованных токенах — и длительность каждого запроса. Затем измените начало и повторите опыт. Совпадение текста само по себе ещё не доказывает попадание в кэш: смотрите показатели чтения и записи кэша в ответе API.

## Из чего складывается цена

```text
стоимость запроса = обычный вход × тариф входа
                  + запись кэша × тариф записи
                  + чтение кэша × тариф чтения
                  + ответ модели × тариф выхода
```

Для полной задачи сложите расходы всех запросов. История растёт, инструмент может вернуть длинный ответ, а неудачную попытку приходится повторять. Поэтому цена одного короткого запроса не показывает цену всей работы.

В актуальном Claude Code `/usage` показывает данные сессии и ограничения использования, а `/cost` служит другим именем этой команды. Это описано в [справочнике команд](https://code.claude.com/docs/en/commands). Денежная оценка в клиенте может отличаться от фактического счёта. Подписка и API оплачиваются по-разному: сверяйте итог с [документацией расходов](https://code.claude.com/docs/en/costs) и своим счётом.

## Когда пора начать новый разговор

Если история перегружена, сначала сохраните задачу, принятые решения, изменённые файлы и результаты проверок. Допишите следующий шаг. Эта короткая запись полезнее обещания «агент всё помнит».

После `/clear` продолжайте с сохранённого описания. А постоянные правила проекта лучше хранить в [CLAUDE.md](/courses/claude-code-guide/03-claude-md/).
