Модель может ответить пользователю текстом, а может запросить действие: например, поиск маршрутов. Такой запрос называется вызовом инструмента — _tool call_. Для инструмента, который исполняется в вашем приложении, именно приложение проверяет аргументы, запускает поиск и возвращает результат модели.

Это описание относится к вашим, клиентским инструментам. У API также бывают серверные инструменты, которые выполняет поставщик. Различие и форматы `tool_use` и `tool_result` описаны в [руководстве Anthropic](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview).

## Один круг работы

Пользователь спрашивает о поездке. Модель выбирает поиск и передаёт города с датой. Приложение проверяет запрос, вызывает поиск и отправляет найденные варианты обратно. Теперь модель может объяснить результат или запросить уточнение.

У каждого вызова есть идентификатор. Ответ инструмента связывается с ним, чтобы модель не перепутала результаты разных действий. Нельзя просто заменить всё сообщение модели обычной строкой: в нём могут быть и текст, и запросы инструментов.

## Где цикл должен остановиться

Ниже схема, а не готовый код для конкретного SDK:

```text
пока не превышены число шагов и время работы:
    запросить ответ модели и сохранить его в истории
    если модель запросила инструменты:
        проверить имена, аргументы и разрешения
        выполнить допустимые вызовы с ограничением времени
        вернуть успех или ошибку с идентификатором каждого вызова
    иначе:
        проверить причину остановки и результат задачи
        вернуть ответ или явно сообщить, что задача не завершена
при достижении лимита:
    сохранить состояние и сообщить об остановке
```

Завершение ответа модели не доказывает выполнение вашей задачи. Например, остановка по `max_tokens` означает достижение лимита вывода. Проверка результата всё равно нужна.

## Не превращайте ошибку в отсутствие данных

Если поиск не ответил вовремя, сообщите о превышении времени ожидания. Пустой список в этом случае вводит в заблуждение: пользователь услышит «маршрутов нет», хотя поиск не завершился.

Также не повторяйте любое действие автоматически. Повтор чтения часто допустим, а повтор бронирования может создать второй заказ. После сетевого сбоя первое действие уже могло произойти. Защиту от повторного эффекта нужно проектировать отдельно.

## Попробуйте без настоящего API

Создайте тестовый поиск с тремя исходами: найден маршрут, неверная дата, превышено время ожидания. Добавьте неизвестный инструмент и отказ в доступе. Убедитесь, что ответы связаны с правильными вызовами, ошибки различаются и цикл останавливается на заданном лимите.

Независимые чтения можно запускать одновременно. А изменение файла и проверка этого изменения должны идти по порядку. Деление более крупных задач между помощниками разберём в [следующем уроке](/courses/claude-code-guide/09-subagents/).
