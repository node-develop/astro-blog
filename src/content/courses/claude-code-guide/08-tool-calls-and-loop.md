Модель может предложить вызов инструмента. Исполнить его, проверить аргументы и вернуть результат должно приложение. Полезно рассматривать этот обмен как протокол: каждому вызову соответствует идентификатор, а ответ должен быть связан именно с ним.

В Anthropic API используются блоки `tool_use` и `tool_result`; детали доступны в [руководстве tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview). Не все блоки ответа являются текстом, поэтому нельзя без проверки читать у каждого потокового события поле text.

## Схема цикла

Это псевдокод, а не готовый SDK-пример:

```text
пока не превышены лимит шагов и срок выполнения:
    получить ответ модели
    сохранить ответ в истории
    если это завершённый ответ:
        вернуть результат пользователю
    если запрошены инструменты:
        для каждого вызова:
            проверить имя, аргументы и права
            исполнить с timeout
            сохранить успех или ошибку с исходным call id
        передать результаты модели
    иначе:
        обработать причину остановки явно
при достижении лимита:
    вернуть незавершённый статус и сохранённое состояние
```

`max_tokens` не означает успешное завершение задачи. Нельзя бесконечно повторять запрос, не проверяя, продвигается ли работа.

## Ошибка — тоже часть контракта

Предположим, поиск маршрутов вернул timeout. Ответ инструмента должен обозначить ошибку, а не пустой список поездок. Иначе агент может сказать «рейсов нет», хотя поиск не состоялся.

Разделяйте временный сбой, некорректный ввод и отсутствие данных. Повторять имеет смысл только те операции, для которых это допустимо. Бронирование или публикация требуют защиты от повторного эффекта; повтор сетевого запроса после timeout не доказывает, что первое действие не произошло.

## Параллельность

Два независимых чтения можно выполнять одновременно. Запись и следующая проверка этой записи имеют зависимость. Параллельный запуск всех tool calls подряд не является универсальной оптимизацией.

## Упражнение

Создайте фиктивный инструмент с тремя ответами: успех, ошибка ввода и timeout. Проверьте, что каждое обращение получает результат с правильным ID, история сохраняется, а цикл останавливается на лимите. Добавьте случай неизвестного инструмента и отказа в доступе.

Критерий: приложение сообщает правду о состоянии задачи, не повторяет побочный эффект без контроля и не зависает навсегда. Затем подключайте настоящий API и измеряйте полный путь до принятого результата.
