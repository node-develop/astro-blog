Hook запускает обработчик на событие Claude Code. Это удобнее просьбы «не забудь проверить», когда нужно автоматически выполнить небольшое действие. Однако результат зависит от события, matcher, настроек и успешности самого обработчика.

## Начните с наблюдения

В тестовом репозитории добавьте в `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node .claude/hooks/observe-edit.mjs",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

Создайте `.claude/hooks/observe-edit.mjs`:

```javascript
let input = "";
for await (const chunk of process.stdin) input += chunk;
const event = JSON.parse(input);
process.stderr.write(`Observed tool: ${String(event.tool_name)}\n`);
```

Пример только показывает событие, ничего не форматирует и не блокирует. Не записывайте полный stdin в общий лог: там может находиться содержимое файлов или аргументы с чувствительными данными.

## Проверка в два этапа

Сначала передайте скрипту тестовый JSON через stdin. Затем попросите Claude изменить безвредный файл в том же репозитории. Убедитесь, что обработчик действительно запускается. Повторите с неправильным JSON и проверьте, что ошибка видна.

Только после этого подключайте реальный линтер. Проверьте рабочую директорию, наличие зависимостей, timeout и влияние повторного запуска на файл.

## Блокировка зависит от события

[Справочник hooks](https://code.claude.com/docs/en/hooks) описывает отдельные протоколы решений. Для `PreToolUse` ненулевой ответ нужно трактовать по его правилам; exit code 2 может запретить вызов. JSON решения требует корректной структуры события. Старый пример `{"action":"block"}` не является универсальной командой блокировки и удалён из курса.

`PostToolUse` уже выполняется после инструмента: не используйте его как обещание предотвратить запись. Также нельзя обещать, что фильтр `Edit|Write` остановит изменение файла через Bash или другой инструмент.

## Чего hook не заменяет

Regex, ищущий `rm -rf`, не является полноценным анализатором shell и не защищает от всех способов удаления. Не храните production-ключи в учебной среде. Ограничивайте доступ на уровне среды и проверяйте реальные права.

Автоматический `git add -A` с обходом проверок также убран: он может захватить чужие изменения и секреты. Для checkpoint сначала осмотрите diff и выберите конкретные файлы.
