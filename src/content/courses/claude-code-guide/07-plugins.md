Плагин нужен, когда один набор skills, hooks или агентов используется в нескольких проектах. Он упаковывает уже работающие части. Ошибочный hook после упаковки остаётся ошибочным hook, только распространяется быстрее.

## Минимальная структура

```text
trip-toolkit/
  .claude-plugin/plugin.json
  skills/review-contract/SKILL.md
```

Манифест:

```json
{
  "name": "trip-toolkit",
  "version": "0.1.0",
  "description": "Contract review exercises for the trip planner"
}
```

В SKILL.md положите процедуру из [урока про skills](/courses/claude-code-guide/04-skills/). Затем выполните из родительского каталога:

```bash
claude plugin validate ./trip-toolkit
claude --plugin-dir ./trip-toolkit
```

Локальная загрузка позволяет проверить пакет до распространения. Формат каталогов и команды описаны в [документации plugins](https://code.claude.com/docs/en/plugins) и [справочнике](https://code.claude.com/docs/en/plugins-reference).

## Что проверять

Плагин должен загрузиться, показать свой skill и выполнить процедуру на подготовленном примере. Проверьте также запуск из другого рабочего каталога: относительный путь к скрипту может случайно зависеть от места, где вы разрабатывали пакет.

Если добавляете hooks/hooks.json, сохраняйте внешнее поле `hooks`. Если ссылаетесь на скрипты внутри пакета, используйте документированные переменные корня плагина и корректно заключайте путь в кавычки. Не рассчитывайте, что у получателя установлены ваши глобальные npm-пакеты.

## Что написать в README

Укажите назначение, минимальную проверенную версию клиента, зависимости, устанавливаемые компоненты и операции с побочными эффектами. Добавьте один запрос для проверки и ожидаемый результат. Если нужна переменная окружения, опишите её имя и назначение без значения секрета.

Версию повышайте вместе с изменением поведения. В changelog отдельно отмечайте новые инструменты или права. Пользователю должно быть понятно, почему обновление требует другой среды.

## Упражнение

Перенесите пакет в новую временную папку и повторите установку по собственному README. Любой недостающий шаг — дефект документации. Для начала достаточно локального плагина; marketplace не нужен, пока нечего воспроизводимо устанавливать.

Прежние псевдокоманды установки вида `github:...` и неподтверждённые поля manifest удалены. Дальше: [tool calls](/courses/claude-code-guide/08-tool-calls-and-loop/).
