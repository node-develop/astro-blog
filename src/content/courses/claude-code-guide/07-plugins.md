Если один навык используется в нескольких проектах, копировать его вручную неудобно: в одной папке уже новая версия, в другой осталась старая. Плагин позволяет собрать навыки, обработчики событий и другие расширения в один пакет.

Начните с того, что уже работает отдельно. Для первого плагина достаточно навыка проверки API из четвёртого урока.

## Собираем пакет

Создайте такую структуру:

```text
trip-toolkit/
  .claude-plugin/plugin.json
  skills/review-contract/SKILL.md
```

В `.claude-plugin/plugin.json` поместите описание пакета — манифест:

```json
{
  "name": "trip-toolkit",
  "version": "0.1.0",
  "description": "Contract review exercises for the trip planner"
}
```

В SKILL.md скопируйте [процедуру проверки API](/courses/claude-code-guide/04-skills/). Обратите внимание: каталог skills находится рядом с `.claude-plugin`, а не внутри него.

Из родительского каталога выполните:

```bash
claude plugin validate ./trip-toolkit
claude --plugin-dir ./trip-toolkit
```

Первая команда проверяет структуру пакета. Вторая загружает его в запущенную сессию. Навык плагина вызывается с префиксом имени пакета: `/trip-toolkit:review-contract`. Укажите ему проверяемый адрес API. Имена и команды описаны в [руководстве по плагинам](https://code.claude.com/docs/en/plugins).

## Проверяем больше, чем загрузку

Успешная загрузка ещё не означает, что процедура полезна. Дайте навыку пример с известной ошибкой, затем правильный пример. Он должен различать их и ссылаться на реальные файлы.

Повторите запуск из другого рабочего каталога. Если скрипт работает только рядом с папкой, где вы его написали, в пакете есть скрытая зависимость от пути. Для ресурсов плагина используйте документированные переменные, например `CLAUDE_PLUGIN_ROOT`, и заключайте пути с пробелами в кавычки. Форматы файлов приведены в [справочнике](https://code.claude.com/docs/en/plugins-reference).

## Пишем инструкцию установки

В README укажите, для чего нужен плагин, с какой версией клиента вы его проверили и какие программы должны быть установлены. Добавьте одну команду запуска, пример запроса и ожидаемый результат.

Если пакет меняет файлы или обращается к сети, объясните это заранее. Имена нужных переменных окружения можно публиковать, значения секретов — нельзя.

## Небольшое упражнение

Перенесите пакет в новую временную папку и следуйте только собственному README. Каждый недостающий шаг допишите. Для такой проверки не нужен каталог распространения плагинов: сначала добейтесь повторяемой локальной установки.
