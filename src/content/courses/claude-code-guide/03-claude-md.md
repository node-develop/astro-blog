Каждый новый разговор с агентом легко начать с одних и тех же объяснений: где лежит код, как запускать тесты, что нельзя менять. CLAUDE.md позволяет записать эти сведения один раз и поддерживать их рядом с проектом.

Начните с трёх вопросов: что это за приложение, где искать нужную часть и как проверить изменение. Чем конкретнее ответы, тем меньше агенту приходится угадывать.

## Небольшой пример

```markdown
# Планировщик поездок

Учебное приложение: ищет маршруты в тестовых данных, без бронирований.

## Перед изменением

- Найди обработчик запроса и тесты для него.
- Сохрани существующий формат ответа.
- Не подключай внешние сервисы в задаче про проверку дат.

## Проверка

Найди команду проверки в package.json и README этого проекта.
В отчёте укажи, что запустил и какой результат получил.
```

Последняя часть пока общая. Когда проект появится, замените её настоящей командой. Например, `pnpm test` имеет смысл только в репозитории, где такая команда определена. Правдоподобная, но несуществующая инструкция будет мешать при каждом запуске.

## Куда положить подробности

Общие правила оставьте в корневом файле. Длинное описание отдельной подсистемы вынесите рядом с её кодом. Для повторяющейся процедуры, например проверки API, подойдёт отдельный навык — его создадим в следующем уроке.

[Документация CLAUDE.md и памяти](https://code.claude.com/docs/en/memory) описывает импорт через `@path`. Он загружает содержимое другого файла. Это способ разложить инструкции по файлам, а не уменьшить объём загружаемого текста. Обычная ссылка на справочник и импорт всего справочника работают по-разному.

Не путайте CLAUDE.md с MEMORY.md: второй относится к автоматической памяти Claude Code. Правила загрузки одного файла нельзя автоматически переносить на другой.

## Проверьте инструкции как часть проекта

Пройдите по каждой строке. Указанный путь существует? Команда запускается? Ограничение всё ещё нужно? Если два файла требуют противоположных действий, исправьте сами инструкции, а не надейтесь, что модель выберет нужную.

Затем попросите агента объяснить порядок работы над проверкой дат. Хороший ответ ссылается на ваши реальные файлы и проверки. Если агент предлагает другой порядок, разберитесь, какое правило оказалось непонятным или потерялось среди лишнего текста.

## Что этот файл не делает

Фраза «не читай секреты» полезна как инструкция, но сама по себе не закрывает доступ к файлам. Права на чтение, запуск команд и сеть настраиваются отдельно. Проверяйте их в учебной среде, где нет рабочих ключей.
