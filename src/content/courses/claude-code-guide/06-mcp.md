Представьте, что у вас уже есть поиск маршрутов и вы хотите дать Claude Code возможность им пользоваться. MCP — протокол, через который приложение подключается к серверу инструментов и данных. Он описывает обмен сообщениями, но не гарантирует правильность найденных маршрутов.

Удобно разделить две проверки: сначала убедиться, что соединение работает, затем проверить, что сам поиск правильно обрабатывает запросы.

## Подключаем локальный сервер

Для этого упражнения нужен заранее подготовленный MCP-сервер с тестовыми маршрутами. Команда ниже только подключает его — она не создаёт реализацию поиска. Замените путь на настоящий собранный файл сервера:

```bash
claude mcp add --transport stdio --scope local trip-fixtures -- node /absolute/path/trip-tools/server.mjs
claude mcp get trip-fixtures
claude mcp list
```

`stdio` означает обмен через стандартные потоки запущенного процесса. `--scope local` ограничивает настройку текущим проектом для вашего пользователя. В сессии Claude Code откройте `/mcp` и проверьте состояние подключения.

По [документации Claude Code](https://code.claude.com/docs/en/mcp), личные настройки local и user хранятся в `~/.claude.json`, а общая настройка проекта — в `.mcp.json`. Это разные области действия настройки, а не разные права самого инструмента.

Для удалённого подключения используется HTTP. В [спецификации MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) описан Streamable HTTP, в том числе возможность потока серверных сообщений. Не смешивайте его с прежним транспортом HTTP+SSE.

## Что должен делать поиск

Пусть инструмент `search_trips` принимает `origin`, `destination` и `date`: пункт отправления, пункт назначения и дату. В результате нужны идентификатор варианта, цена, валюта и источник данных. Для учебных предложений явно укажите, что цены тестовые.

Проверьте четыре запроса: правильный, с неизвестным городом, с неверной датой и без подходящих маршрутов. Последний случай особенно важен: пустой список должен означать выполненный поиск, а не сбой соединения.

## От подключения к приложению

Если пишете собственный клиент, берите пример из [официального TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk) для выбранной версии пакета. Сначала установите соединение без модели. Так ошибку протокола будет проще отличить от неправильного решения агента.

В своём приложении отдельно предусмотрите завершение соединения, время ожидания и перевод ошибок в понятный ответ. Настроенный MCP в Claude Code не добавляет эту логику в ваш серверный код.

Упражнение завершено, когда инструмент доступен и все четыре случая дают ожидаемый результат. Несколько таких расширений можно собрать в [плагин](/courses/claude-code-guide/07-plugins/).
