Команда полезна, когда части задачи действительно можно выполнять независимо. Если backend ждёт схему, а тесты ждут backend, запуск трёх исполнителей не делает всю цепочку параллельной.

[Документация agent teams](https://code.claude.com/docs/en/agent-teams) описывает координацию отдельных сессий и отмечает экспериментальные ограничения. Настройку включения сверяйте с используемой версией. Старые команды `/team add`, `/team kill` и обещание автоматических блокировок исходных файлов удалены из курса: блокировка при назначении задачи не равна защите каждого редактируемого файла.

## Пример разделения работы

Для учебного Travel Agent добавим возможность поделиться маршрутом. До запуска исполнителей согласуйте контракт: какие данные публичны, как выглядит ссылка, что происходит после удаления маршрута.

| Часть                         | Владелец        | Зависимость                |
| ----------------------------- | --------------- | -------------------------- |
| Схема хранения ссылки         | Исполнитель A   | Согласованный контракт     |
| Endpoint чтения               | Исполнитель A   | Схема                      |
| Кнопка и состояния интерфейса | Исполнитель B   | Контракт, сначала фикстуры |
| Интеграционная проверка       | Основная сессия | Готовые обе части          |

Здесь два исполнителя имеют смысл только при достаточном объёме работы. Отдельный агент на описание одного предложения в PR может стоить больше координации, чем сама задача.

## Передайте границы явно

В задании укажите принадлежащие исполнителю файлы, ожидаемый результат, доступные фикстуры и порядок передачи изменений. Сообщите, что рядом работает другой исполнитель и его правки нельзя откатывать.

Если два участника должны изменить один файл, назначьте одного владельца или договоритесь об последовательности. Не рассчитывайте на несуществующий lock API из старого текста.

## Проверка интеграции

Соберите изменения в одной рабочей копии, прочитайте общий diff и запустите сценарий целиком. Успешные отдельные тесты не доказывают, что UI и backend используют одинаковые поля.

Проверьте отказ: удалённый маршрут, недоступный endpoint, истёкшая ссылка. Затем завершите ненужные сессии и убедитесь, что не осталось незавершённых изменений.

## Упражнение

Сначала выполните небольшую задачу одной сессией. Для следующей сопоставимой задачи запишите время постановки, ожидания, интеграции и расход всех участников. Это даст основание решать, окупается ли команда в вашем процессе, без универсального обещания ускорения.
