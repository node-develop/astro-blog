Когда основной агент занят изменением кода, отдельному помощнику можно поручить поиск нужных файлов или разбор тестов. В Claude Code такой помощник называется _subagent_. Ему лучше давать законченную задачу с небольшим результатом, а не неопределённое «посмотри проект».

Например: найти схему запроса, обработчик и тесты для проверки дат. Основной агент получит краткий ответ вместо длинной истории поиска.

## Описываем помощника

Создайте `.claude/agents/contract-reader.md`:

```markdown
---
name: contract-reader
description: Находит схему запроса, обработчик и тесты указанного API.
tools: Read, Grep, Glob
model: sonnet
---

Верни пути файлов и объясни, как данные доходят до обработчика.
Отделяй найденные факты от предположений.
Если указанный адрес API отсутствует, сообщи об этом.
Сначала установи текущее поведение, затем обсуждай изменения.
```

Попросите Claude использовать `contract-reader` и укажите конкретный адрес API. Поле `tools` здесь ограничивает набор инструментов помощника чтением и поиском. Не путайте его с `allowed-tools` у навыка: назначение этих полей различается.

## Что помощник знает о задаче

Обычный помощник из такого файла получает своё описание и переданное ему задание. Не полагайтесь на то, что он автоматически знает всю переписку. В актуальном Claude Code есть также ответвления разговора — _forks_, которые наследуют историю основной сессии. Это другой способ запуска; возможности зависят от версии клиента.

Поддерживаемые поля, память и различия этих режимов описаны в [справочнике помощников](https://code.claude.com/docs/en/sub-agents). Если добавляете `memory`, выбирайте документированную область памяти: `user`, `project` или `local`. Это настройка хранения, а не обозначение доступа «только чтение».

## Проверяем результат

Дайте помощнику существующий адрес API и проверьте, что указанные файлы действительно есть. Затем передайте несуществующий адрес. Честный ответ об отсутствии обработчика полезнее выдуманной ссылки.

Сравните с выполнением той же задачи без помощника. Учтите время постановки, уточнения и расходы обоих участников. Короткий итоговый ответ не означает, что поиск был бесплатным.

## Если помощник меняет файлы

Отдельный разговор не защищает от одновременной правки одного файла. Назначьте владельцев изменений или используйте отдельные рабочие копии Git — `worktree`. Они разделяют файлы, но не изолируют сеть и внешние сервисы.

Перед объединением изменений прочитайте разницу версий и выполните проверки. Даже несохранённая в коммите правка — уже работа, которую нельзя случайно затереть. Следующий шаг — [координация команды агентов](/courses/claude-code-guide/10-agent-teams/).
