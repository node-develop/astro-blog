Если статья не индексируется, первым делом проверьте доступ Googlebot и ответ сервера. Разрешение GPTBot или наличие llms.txt не объясняет, почему Google выбрал или не выбрал страницу для индекса.

На artka.dev публичные статьи разрешены для обхода. Закрыты `/admin/` и `/api/`; страницы внутреннего поиска доступны для чтения роботом, но отдают noindex. Это разные решения с разными целями.

## Разделите три задачи

| Задача                                     | Что проверять                                                   |
| ------------------------------------------ | --------------------------------------------------------------- |
| Появление в Google Search                  | Googlebot, HTTP-ответ, noindex, canonical и полезность страницы |
| Использование для обучения моделей         | Правила соответствующего training-бота                          |
| Получение страницы по запросу пользователя | Поведение конкретного сервиса и его fetch-бота                  |

У [OpenAI](https://developers.openai.com/api/docs/bots) GPTBot относится к обучению, OAI-SearchBot — к поиску. ChatGPT-User получает страницы по действию пользователя; для таких запросов robots.txt может не применяться. Разрешение одного бота не следует трактовать как настройку всех остальных.

В [документации Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler) указаны ClaudeBot, Claude-SearchBot и Claude-User. В прежней версии статьи использовались устаревшие названия Claude-Web и anthropic-ai; они заменены актуальными.

Google-Extended также не является переключателем индексации Google Search. Проверяйте назначение токена в [списке Google crawlers](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers).

## Простой пример политики

Если сайт разрешает публичный контент всем роботам, базовый файл может выглядеть так:

```text
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/

Sitemap: https://artka.dev/sitemap-index.xml
```

Действующая политика сайта опубликована в [robots.txt](/robots.txt). Именованные группы в ней повторяют ограничения закрытых маршрутов. Если добавляете отдельную группу, проверьте её полностью: не рассчитывайте, что ограничения из `*` автоматически дополнят более конкретную группу.

robots.txt — публичный файл. Он не должен содержать секретных адресов или токенов. И он не защищает данные от клиента, который игнорирует правила: для закрытого API нужна аутентификация.

## Почему noindex нельзя прятать за Disallow

Чтобы увидеть HTML-директиву noindex, робот должен получить страницу. Если запретить её обход в robots.txt, Google может не прочитать эту директиву. Поэтому внутренний поиск на сайте остаётся доступным для обхода и исключается из индекса через noindex. [Google объясняет это ограничение](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

Для статьи проверьте обычный GET, не только HEAD:

```bash
curl -sS -D /tmp/article-headers.txt \
  https://artka.dev/blog/robots-txt-ai-crawlers-2026/ \
  -o /tmp/article.html
```

В заголовках нужен корректный HTTP-статус и отсутствие нежелательного `X-Robots-Tag: noindex`. В HTML — статья, собственный canonical и отсутствие нежелательного meta robots. Если есть редирект, проверьте и конечный адрес: первый 301 может вести на 404.

Подмена User-Agent через curl показывает ответ сервера на выбранную строку, но не доказывает доступ настоящего Googlebot: CDN может отдельно проверять адрес и происхождение запроса. Для этого полезна проверка опубликованного URL в Search Console.

## Что делать с llms.txt

На этом сайте [llms.txt](/llms.txt) — дополнительный каталог материалов для клиентов, которые хотят его использовать. Он не заменяет HTML, sitemap и обычные ссылки. [Google уточнил](https://developers.google.com/search/updates), что llms.txt не требуется для Google Search и не влияет на видимость или позиции.

Поэтому при восьми индексируемых страницах приоритет — корректные адреса, доступный контент и содержательное обновление. Добавлять десятки имён ботов ради надежды на рост органики бессмысленно без конкретной цели политики доступа.

После исправления страницы можно запросить повторное сканирование через URL Inspection. Это просьба об обходе, а не гарантия индексации; [Google предупреждает](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), что повторные запросы не ускоряют процесс.
